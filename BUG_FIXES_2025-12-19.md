# Bug Fixes Summary - 2025-12-19

## Issues Fixed

### 1. ❌ ML Anomaly Detection Feature Mismatch Error
**Error Message:**
```
❌ Error predicting anomaly: The feature names should match those that were passed during fit.
Feature names seen at fit time, yet now missing:
- hr_std
- temp_std
```

**Root Cause:**
The ML model was trained with 8 features (including `hr_std` and `temp_std`), but during prediction, only the first 6 features were being used.

**Fix Applied:**
- Updated `ml_disease_detector.py` line 220-228
- Changed from using `self.feature_names[:6]` to using all 8 features explicitly
- Now includes: `temperature`, `heart_rate`, `motion_magnitude`, `temp_change_rate`, `hr_change_rate`, `motion_variability`, `temp_std`, `hr_std`

**File Modified:**
- `app/services/ml_disease_detector.py`

### 2. ❌ Database Schema Error - Missing Temperature Column
**Error Message:**
```
❌ Error creating alerts: table alerts has no column named temperature
```

**Root Cause:**
The alerts table schema was updated to include `temperature`, `heart_rate`, and `battery` columns, but existing databases didn't have these columns.

**Fix Applied:**
- Added automatic database migration in `lora_service.py`
- Checks for missing columns using `PRAGMA table_info(alerts)`
- Automatically adds missing columns: `temperature`, `heart_rate`, `battery`
- Migration runs on first alert creation after startup

**File Modified:**
- `app/services/lora_service.py` (lines 290-306)

---

### 3. ⚠️ WebSocket Event Loop Error
**Error Message:**
```
⚠️  Could not broadcast update: There is no current event loop in thread 'Thread-1 (_monitor_loop)'.
```

**Root Cause:**
The LoRa monitoring service runs in a background thread (`Thread-1`), but it was trying to call async WebSocket functions using `asyncio.get_event_loop()`, which doesn't work from non-async threads.

**Fix Applied:**
1. **Updated `app/websocket/handlers.py`:**
   - Added `_main_loop` global variable to store the main event loop reference
   - Added `set_event_loop(loop)` function to set the loop from the main thread
   - Updated `broadcast_update()` to use `asyncio.run_coroutine_threadsafe()` for thread-safe async calls

2. **Updated `run.py`:**
   - Added event loop initialization in `startup_event()`
   - Calls `set_event_loop()` with the running event loop
   - This allows background threads to safely schedule async tasks

**Files Modified:**
- `app/websocket/handlers.py`
- `run.py`

## Technical Details

### Thread-Safe WebSocket Broadcasting
The new implementation uses `asyncio.run_coroutine_threadsafe()` which:
- Allows background threads to schedule coroutines in the main event loop
- Returns a `concurrent.futures.Future` object
- Safely handles cross-thread async operations
- Prevents "no event loop in thread" errors

### Database Migration Strategy
The migration approach:
- Non-destructive: only adds columns, never removes
- Automatic: runs on first use
- Idempotent: safe to run multiple times
- Uses SQLite's `PRAGMA table_info()` to check existing schema

### ML Feature Consistency
The fix ensures:
- Training and prediction use identical feature sets
- All 8 features are explicitly listed
- Features are filled with 0 if missing (using `.fillna(0)`)
- Prevents sklearn's feature mismatch errors
